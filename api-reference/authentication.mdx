Every request to the Progress Pilot REST API must be authenticated using an API key. Keys are passed as a Bearer token in the `Authorization` header. There are no session cookies, no OAuth flows required for server-to-server integrations — just include your key in every request and you're authenticated. You can generate and revoke API keys at any time from the **Settings → API Keys** page in your Progress Pilot dashboard.

## API Key Types

Progress Pilot issues two types of API keys so that you can safely test integrations without touching real production data.

| Key Prefix | Environment | Behavior |
|---|---|---|
| `ppk_live_...` | Production | Full access to live data. Actions taken with live keys are real and permanent. |
| `ppk_test_...` | Development / Testing | Sandboxed environment. No real meetings, reports, or notifications are triggered. |

<Info>
  Test keys return realistic mock data that mirrors the shape of live responses, making them ideal for building and validating your integration before going live.
</Info>

## Authenticating Requests

Pass your API key in the `Authorization` header using the `Bearer` scheme. This applies to every HTTP method — `GET`, `POST`, `PATCH`, and `DELETE`.

<Tabs>
  <Tab title="cURL">
    ```bash
    curl https://api.progresspilot.ai/v1/meetings \
      -H "Authorization: Bearer ppk_live_your_api_key"
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import requests

    headers = {
        "Authorization": "Bearer ppk_live_your_api_key",
        "Content-Type": "application/json"
    }

    response = requests.get(
        "https://api.progresspilot.ai/v1/meetings",
        headers=headers
    )

    data = response.json()
    ```
  </Tab>
  <Tab title="Node.js">
    ```javascript
    const response = await fetch('https://api.progresspilot.ai/v1/meetings', {
      headers: {
        'Authorization': 'Bearer ppk_live_your_api_key',
        'Content-Type': 'application/json'
      }
    });

    const data = await response.json();
    ```
  </Tab>
</Tabs>

## Generating an API Key

<Steps>
  <Step title="Open your dashboard">
    Log in to [app.progresspilot.ai](https://app.progresspilot.ai) and navigate to **Settings** in the left sidebar.
  </Step>
  <Step title="Go to API Keys">
    Select the **API Keys** tab. You'll see any existing keys along with their last-used timestamps.
  </Step>
  <Step title="Create a new key">
    Click **New API Key**, give it a descriptive name (e.g. `production-integration` or `ci-testing`), select the appropriate environment, and click **Generate**.
  </Step>
  <Step title="Copy and store the key immediately">
    Your full API key is only displayed once at creation time. Copy it and store it securely — in a secrets manager or environment variable — before closing the dialog.
  </Step>
</Steps>

<Warning>
  Progress Pilot cannot show you the full key again after you close the creation dialog. If you lose a key, revoke it immediately and generate a new one.
</Warning>

## Authentication Errors

If a request fails authentication or authorization, the API returns a structured error response with one of the following error codes.

| Error Code | HTTP Status | Cause | Fix |
|---|---|---|---|
| `INVALID_API_KEY` | 401 | The key does not exist or has been revoked. | Generate a new key in the dashboard. |
| `EXPIRED_API_KEY` | 401 | The key has passed its configured expiry date. | Rotate the key and update your integration. |
| `INSUFFICIENT_PERMISSIONS` | 403 | The key exists but lacks the required scope for this endpoint. | Use a full-access key or adjust key permissions. |
| `RATE_LIMIT_EXCEEDED` | 429 | Too many requests in the current window. | Implement exponential backoff and retry logic. |

A `401` error response looks like this:

```json
{
  "success": false,
  "error": {
    "code": "INVALID_API_KEY",
    "message": "The provided API key is invalid or revoked.",
    "docs_url": "https://docs.progresspilot.ai/api-reference/authentication"
  }
}
```

## Security Best Practices

Following these practices keeps your integration and your customers' data safe.

<Warning>
  Never expose your API keys in client-side code — including frontend JavaScript, mobile apps, or public repositories. Any key visible in client-side code can be extracted and abused. All Progress Pilot API calls must be made from your backend server.
</Warning>

- **Use environment variables.** Store keys in environment variables (e.g. `PROGRESS_PILOT_API_KEY`) rather than hardcoding them in source files. Use a secrets manager like AWS Secrets Manager, HashiCorp Vault, or Doppler for production systems.
- **Use separate keys per environment.** Maintain distinct keys for development, staging, and production. This limits the blast radius if a key is compromised and makes it easy to rotate without disrupting other environments.
- **Rotate keys regularly.** Even if a key hasn't been compromised, rotate it on a regular schedule — at minimum every 90 days for production keys.
- **Revoke unused keys immediately.** If you stop using an integration or an employee with key access leaves your organization, revoke the associated key right away.
- **Monitor key usage.** Review the last-used timestamps and request logs in the dashboard to detect any unexpected usage patterns.

<Tip>
  You can set an optional expiry date when creating an API key. Progress Pilot will return `EXPIRED_API_KEY` errors after that date, prompting you to rotate on a predictable schedule.
</Tip>
