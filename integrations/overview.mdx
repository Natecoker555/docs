Progress Pilot becomes dramatically more powerful when connected to the tools your team already uses. Rather than asking you to change how you work, Progress Pilot meets your team where it is — reading your calendar, joining your meetings, posting to your Slack channels, and pulling data from your databases to generate the insights and reports that used to take hours to compile manually. Every integration is built on secure, auditable, OAuth-based authentication with scoped permissions you control.

## How Integrations Work

Every integration in Progress Pilot follows a consistent security model designed to give you full visibility and control over what the agent can access.

**OAuth 2.0 and API Key authentication** — Most integrations use the OAuth 2.0 authorization code flow. You grant permissions directly through the provider's official consent screen; Progress Pilot never sees or stores your passwords. For tools that use API keys (such as Linear), you generate a scoped token in the provider's settings and paste it into Progress Pilot.

**Scoped permissions** — Progress Pilot only requests the minimum permissions needed to perform its functions. For example, connecting Google Calendar requests read-only calendar access; it does not request the ability to create or delete events unless you explicitly enable scheduling features.

**Revocable at any time** — You can disconnect any integration from **Settings → Integrations** instantly. Revoking access in Progress Pilot also prompts you to revoke the OAuth grant in the connected provider, ensuring no lingering access remains.

**Per-workspace isolation** — Each Progress Pilot workspace maintains its own set of integration credentials. Connections granted in one workspace are never shared with another, even within the same organization.

<Note>
  All OAuth tokens are encrypted at rest using AES-256 and stored in isolated credential vaults. Tokens are never returned in API responses, never logged, and are only decrypted in memory at the moment they are needed to make an authorized request.
</Note>

## Managing Integrations via API

In addition to the Settings UI, you can manage integrations programmatically using the Progress Pilot REST API. This is useful for automated provisioning, infrastructure-as-code workflows, and enterprise onboarding scripts.

**List all connected integrations for a workspace:**

```http
GET https://api.progresspilot.ai/v1/integrations
Authorization: Bearer <your_api_token>
```

```json
{
  "integrations": [
    {
      "id": "int_01hx9k2p3q",
      "provider": "google_workspace",
      "status": "connected",
      "scopes": ["calendar.readonly", "documents", "gmail.send"],
      "connected_at": "2024-11-14T09:22:11Z",
      "connected_by": "user_01hx3m7r8t"
    },
    {
      "id": "int_01hx9k4z7w",
      "provider": "slack",
      "status": "connected",
      "scopes": ["channels:write", "chat:write", "commands"],
      "connected_at": "2024-11-14T09:35:44Z",
      "connected_by": "user_01hx3m7r8t"
    }
  ]
}
```

**Initiate a new integration connection:**

```http
POST https://api.progresspilot.ai/v1/integrations/connect
Authorization: Bearer <your_api_token>
Content-Type: application/json

{
  "provider": "jira",
  "redirect_uri": "https://your-app.example.com/oauth/callback"
}
```

```json
{
  "authorization_url": "https://auth.atlassian.com/authorize?client_id=...&redirect_uri=...&scope=read:jira-work",
  "state": "csrf_01hx9kbp2z",
  "expires_in": 300
}
```

Redirect the user to the returned `authorization_url` to complete the OAuth consent flow. The `state` parameter is a CSRF token that Progress Pilot validates when the user is redirected back to your `redirect_uri`.

To disconnect an integration, navigate to **Settings → Integrations** in the Progress Pilot dashboard, find the connected integration, and click **Disconnect**. All associated credentials are immediately purged and the OAuth grant is revoked.
