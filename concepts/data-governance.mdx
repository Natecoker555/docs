As an AI agent that processes meeting transcripts, project data, and organizational reports, Progress Pilot operates at the intersection of productivity and data sensitivity. Giving you meaningful control over that data is not optional — it is central to how the platform is designed. This page covers every governance lever available to you: what data Progress Pilot collects, how long it keeps it, how it handles personally identifiable information, how you classify and protect sensitive outputs, and how to export or permanently delete your data when you need to.

<Tip>
  Configure your workspace's data retention policy before running your first agent task. Once data is created, it falls under whatever retention rules are active at the time of creation. Setting the right policy upfront means you never have to retroactively purge records or deal with data lingering longer than your compliance requirements allow. You can set your retention policy in **Settings → Data Governance → Retention**.
</Tip>

## What Data Progress Pilot Collects

Progress Pilot processes and stores only the data required for the agent to complete tasks and for you to review its outputs. It does not collect behavioral analytics, device telemetry, or any data not directly related to your operational workflows.

| Data Type | Source | Purpose | Stored? |
|---|---|---|---|
| Meeting transcripts (text) | Connected transcription service | Action item extraction, summarization | Yes |
| Raw audio recordings | Meeting platforms | Transcription only — immediately discarded | No |
| Agent task outputs | Generated by the agent | Reports, summaries, action item logs | Yes |
| Tool call inputs and outputs | Integration API responses | Audit logging, context for follow-up tasks | Metadata only |
| User authentication data | OAuth 2.0 / SSO | Identity verification and session management | Yes |
| Workspace configuration | Set by admins | Tool permissions, roles, retention policies | Yes |
| Integration credentials | Set by admins | Secure access to connected systems | Yes (encrypted) |

## Data Lifecycle

<Steps>
  <Step title="Data Ingestion">
    Data enters Progress Pilot when the agent reads from a connected integration (e.g., fetching a meeting transcript or querying a database) or when a task is triggered. At ingestion, data is classified according to any classification tags applied to the source workspace or the specific task.
  </Step>
  <Step title="Active Use">
    During task execution, data is held in the agent's session context (in-memory, never written to disk in raw form) and in the workspace's persistent memory store (encrypted at rest). It is available to the agent for the duration of the task and to authorized users via the dashboard.
  </Step>
  <Step title="Retention Period">
    After creation, each data artifact is subject to the workspace's configured retention period. When the retention period expires, the artifact is automatically scheduled for deletion during the next nightly purge cycle.
  </Step>
  <Step title="Deletion">
    Deleted artifacts are removed from the primary data store immediately and from encrypted backups within 30 days. After deletion, the data cannot be recovered. Deletion events are recorded in the audit log.
  </Step>
</Steps>

## Retention Policies

Progress Pilot provides flexible retention controls so you can align data lifecycle with your legal and operational requirements.

| Plan | Default Retention | Configurable Range |
|---|---|---|
| Starter | 30 days | 7 – 90 days |
| Pro | 90 days | 7 – 365 days |
| Enterprise | 90 days | 7 – 365 days, or custom |

Enterprise customers can request custom retention periods beyond 365 days (for example, to meet 7-year financial record-keeping requirements) or shorter minimums (for example, 24-hour retention for highly sensitive transcript data). Custom retention configurations are applied at the workspace level and can be scoped to specific data types.

To update your retention policy:

```bash
# Update workspace retention via the API
curl -X PATCH https://api.progresspilot.com/v1/workspace/settings/retention \
  -H "Authorization: Bearer ppk_live_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "default_retention_days": 60,
    "overrides": {
      "meeting_transcripts": 30,
      "task_outputs": 90
    }
  }'
```

## PII Handling

Progress Pilot includes automatic PII detection that identifies and masks personally identifiable information in agent outputs — including meeting transcript summaries, reports, and action item logs — before they are stored or distributed.

The following PII categories are detected and masked by default:

<CardGroup cols={2}>
  <Card title="Names" icon="user">
    Individual first and last names appearing in transcript text are replaced with role-based identifiers (e.g., `[Participant 1]`) in exported outputs, while the internal record retains the original for authorized users.
  </Card>
  <Card title="Email Addresses" icon="envelope">
    Email addresses are masked to `[email redacted]` in all exported artifacts. They remain visible in the dashboard to users with the **Manager** or **Admin** role.
  </Card>
  <Card title="Phone Numbers" icon="phone">
    Phone numbers in any common format (international, US, UK) are detected and masked to `[phone redacted]` in exports and summaries.
  </Card>
  <Card title="Custom PII Patterns" icon="sliders">
    Enterprise workspaces can define custom regex-based PII patterns — for example, employee ID formats, internal project codes, or medical record numbers — that are masked alongside the built-in categories.
  </Card>
</CardGroup>

<Note>
  PII masking applies to **exported** artifacts by default. Users with the **Admin** or **Manager** role can view unmasked data within the Progress Pilot dashboard, subject to their role permissions. To enable masked-only views for all roles (including Admins), enable **Strict PII Mode** in **Settings → Data Governance → PII**.
</Note>

To explicitly enable unmasked PII in exports for a specific task (for example, when generating a formal HR report), set the `pii_export` flag in the task configuration:

```json
{
  "task_type": "meeting_summary",
  "meeting_id": "meet_01j8x3kv9f",
  "output": {
    "format": "pdf",
    "pii_export": true
  }
}
```

This flag requires **Admin** or **Manager** role to set, and its use is recorded in the audit log.

## Data Classification

Progress Pilot supports four data classification levels. Classification tags can be applied to workspaces, to individual task outputs, and to custom report templates. They govern who can view, export, and share each artifact.

<Tabs>
  <Tab title="Public">
    **Public** data can be viewed and exported by all workspace members, including **Viewer** role users. Use this classification for outputs you intend to share broadly — for example, a company-wide OKR summary or a published project retrospective.
  </Tab>
  <Tab title="Internal">
    **Internal** is the default classification for all agent outputs. Data tagged as Internal can be viewed by all workspace members but cannot be exported by **Viewer** role users. Sharing links for Internal artifacts require authentication.
  </Tab>
  <Tab title="Confidential">
    **Confidential** data is restricted to **Manager** and **Admin** roles. It cannot be viewed, exported, or shared by **Contributor** or **Viewer** users. Use this classification for reports containing financial projections, headcount data, or strategic planning details.
  </Tab>
  <Tab title="Restricted">
    **Restricted** is the highest classification level. Access is limited to **Admin** role users only, and every access event is flagged in the audit log. Use Restricted for outputs containing legal matter details, executive compensation data, or M&A-sensitive information.
  </Tab>
</Tabs>

To apply a classification tag to a task output via the API:

```json
{
  "task_id": "task_09kz4mp2qw",
  "classification": "confidential"
}
```

Classification tags can also be set as defaults for an entire workspace or for specific task types in **Settings → Data Governance → Classification Defaults**.

## Access Policies

Data access in Progress Pilot follows the role permissions defined in your workspace RBAC configuration. The table below summarizes default access behavior by role and classification level.

| Classification | Admin | Manager | Contributor | Viewer |
|---|---|---|---|---|
| Public | View, Export, Share | View, Export, Share | View, Export | View |
| Internal | View, Export, Share | View, Export, Share | View, Export | View |
| Confidential | View, Export, Share | View, Export | — | — |
| Restricted | View, Export | — | — | — |

For a full description of role permissions, see the [Security](/concepts/security) page.

## Audit Trail

Every data access event in Progress Pilot is recorded in the audit trail — not just mutations, but reads and exports as well. This gives you a complete picture of who has accessed sensitive data and when.

Access events logged include:

- Viewing a report or summary in the dashboard
- Exporting data in any format
- Sharing a task output via a link
- Changing the classification of an artifact
- Updating a retention policy
- Any API call that reads or writes workspace data

Audit logs are available in **Settings → Audit Log** and can be exported in JSON or CSV format. Enterprise customers can configure real-time streaming to their SIEM.

## Exporting Your Data

You can export workspace data at any time in three formats:

<CardGroup cols={3}>
  <Card title="CSV" icon="table">
    Tabular exports of structured data: action item logs, task histories, user activity reports, and retention policy configurations.
  </Card>
  <Card title="JSON" icon="code">
    Full fidelity exports of task outputs, agent reasoning traces, and workspace configuration. Suitable for programmatic processing or archiving.
  </Card>
  <Card title="PDF" icon="file-pdf">
    Formatted document exports of reports and summaries, suitable for distribution to stakeholders outside Progress Pilot.
  </Card>
</CardGroup>

To export all workspace data (for example, before canceling a subscription or migrating to a new workspace):

1. Go to **Settings → Data Governance → Export**
2. Select the data types you want to include
3. Choose your export format
4. Click **Request Export**

Large exports are prepared asynchronously. You will receive an email with a time-limited download link (valid for 72 hours) when the export is ready.

## Deleting Data

### Deleting Specific Records

To delete an individual task output, report, or transcript, select the record in the dashboard and choose **Delete**. Deletion is permanent and cannot be undone. The deletion event is recorded in the audit log.

Via the API:

```bash
curl -X DELETE https://api.progresspilot.com/v1/tasks/task_09kz4mp2qw/output \
  -H "Authorization: Bearer ppk_live_your_api_key"
```

### Purging All Data for a User

To remove all data associated with a specific user (for example, to fulfill a GDPR right-to-erasure request):

```bash
curl -X POST https://api.progresspilot.com/v1/workspace/gdpr/erasure \
  -H "Authorization: Bearer ppk_live_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{ "user_email": "jane.doe@your-company.com" }'
```

This removes all task outputs, transcript references, and audit log entries attributable to that user across the workspace. The request is processed within 30 days in accordance with GDPR Article 17 requirements.

### Deleting an Entire Workspace

Workspace deletion permanently removes all data, configurations, users, and integrations. This action is irreversible.

<Steps>
  <Step title="Export Your Data">
    Before deleting, request a full workspace export from **Settings → Data Governance → Export**. Once deletion is confirmed, no recovery is possible.
  </Step>
  <Step title="Initiate Deletion">
    Go to **Settings → Workspace → Danger Zone → Delete Workspace**. You must be an **Admin** to perform this action.
  </Step>
  <Step title="Confirm with Two-Factor Verification">
    You will be required to re-authenticate and enter a confirmation phrase. This step prevents accidental deletions.
  </Step>
  <Step title="Deletion Processing">
    Active data is deleted immediately. Encrypted backups are purged within 30 days. You will receive a confirmation email when the purge is complete.
  </Step>
</Steps>
